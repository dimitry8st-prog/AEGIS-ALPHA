# Finam: исследовательские котировки

Адаптер читает свечи, справочник инструментов и новости для бумаг из
единого реестра `config/portfolios/russian-research.json`: GAZP, GMKN, SBER,
YDEX и X5 (`<тикер>@MISX`), а также индикатор рынка IMOEX.
Единственный POST — обмен API secret на короткоживущий access token в
`/v1/sessions`. Методов счетов, заявок и сделок в адаптере нет.

## Проверенный контракт

Официальные источники, проверены 22.10.2026:

- [REST, Auth и Bars](https://api.finam.ru/docs/rest/): JSON `{secret: ...}`
  в POST `/v1/sessions`, ответ `{token: ...}`; GET
  `/v1/instruments/{ticker}@MISX/bars`, `timeframe=TIME_FRAME_D`,
  `interval.start_time` включающий и `interval.end_time` исключающий.
- [Авторизация](https://api.finam.ru/getting-started/bystryy-start/poluchit-access-key-i-uvidet-schet/):
  secret передаётся только в тело Auth, рабочие запросы используют access token.
- [История](https://api.finam.ru/getting-started/bystryy-start/poluchit-kotirovku-i-istoriyu/):
  глубина дневных данных — 365 дней. Разбиение запроса на части не расширяет
  доступную серверную историю.
- [Ошибки и формат Authorization](https://api.finam.ru/getting-started/bystryy-start/diagnostika-oshibok-i-dalneyshie-shagi/):
  REST поддерживает Bearer и сырой access token; адаптер использует Bearer.

Каждый fetch получает новую сессию, без предположения о длительности JWT.
Окно ограничено 365 календарными днями и разбивается на части максимум по 31
дню, максимум 12 запросов Bars. Пустой результат остаётся EMPTY. Ошибки 429,
5xx и сети передаются общей ограниченной retry-политике worker; 400/401/403/404
требуют исправления настроек/доступов. Содержимое ошибок сервера и запрос
авторизации не включаются в сообщения исключений.

Цены берутся как Decimal из объектов `{value: "..."}`, без float; объем должен
быть целым неотрицательным. Поддерживается только `raw`: адаптер не объявляет
серверные данные очищенными от дивидендов или сплитов.

RFC3339 timestamp источника преобразуется к календарной дате Europe/Moscow.
Сохранённое время — метка этой даты 23:59:59 MSK, **не фактическое закрытие биржи**.
22.11.2026 Finam вернул свечу GAZP за 15 ноября при запросе с 16 ноября.
Для каждой части запроса адаптер пропускает до одной свечи за календарный день
перед началом интервала и отражает это в `ignored_boundary_rows` для тикера.
Эта свеча не попадает в базу и счётчик `received`. Остальные строки вне
окна, повторные даты и ошибки разбора направляются в карантин с доступными
исходными ячейками. Секреты и JWT в них скрываются.

## Проверка и доступ

MockTransport-тесты не обращаются к брокеру и не используют реальные реквизиты.
Для проверки живого источника нужен API secret из личного кабинета Finam Trade
API, привязанный к разрешённому счёту и правам на рыночные данные. Его следует
передавать процессу как FINAM_API_TOKEN, не в чат, git или аргументы команды.
При отсутствии токена адаптер до HTTP возвращает `FINAM_NOT_CONFIGURED`.

Работа реальной авторизации и доступность исторических данных для конкретного
токена остаются **NOT_VERIFIED** до явного live-запуска с локально настроенным
секретом. Mock-тесты не подтверждают существование или доступность счёта.
Успешная имитация не переводит этот статус в `LIVE_VERIFIED`.

Секрет не входит в образ. `.dockerignore` исключает `.env`, `.env.local`,
прочие `.env.*`, каталог `secrets/` и файлы ключей. Шаблон `.env.example`
в контексте сборки остаётся. Проба `COPY .` с фиктивным значением в
`.env.local` не принесла ни файл, ни эту строку в образ; `worker`, сценарий
и `.env.example` в контексте остались. `Dockerfile` не задаёт
`FINAM_API_TOKEN`. Сервис `market-data-worker` получает токен в окружении
процесса при запуске: `FINAM_API_TOKEN=${FINAM_API_TOKEN:-}`.

Строгая цепочка «сбор → повтор → CSV/manifest» собрана в
`scripts/finam_live_smoke.py` поверх существующих адаптера, pipeline и экспорта.
Без `--live` скрипт не ходит в Finam и не пишет в базу. С `--live` обязательны
две переменные окружения процесса, не аргументы команды: `FINAM_API_TOKEN` и
`FINAM_ACCEPTANCE_DATABASE_URL` (отдельная тестовая база). Сценарий не читает
`.env` и не подставляет рабочий `DATABASE_URL`. Токен, JWT и пароль базы не
печатаются в отчёте и логах. Успех mock — `MOCK_PASSED`; живая приёмка — только
`LIVE_VERIFIED`. Подробности, отдельная база и точная команда:
`docs/RUSSIAN_MARKETS_ACCEPTANCE.md`.

## Прогон сигнала на минутных свечах

Для исследовательских окон по GAZP и GMKN предусмотрен отдельный запрос
`TIME_FRAME_M1` на том же REST-методе Bars. Он сохраняет UTC-метку каждой
свечи для анализа и возвращает данные в память процесса. Выход за
исключающую верхнюю границу окна, дубль или повреждённая строка завершают
прогон ошибкой. Алгоритм проверяет наличие всех минут запрошенного окна.

Из корня репозитория в окружении проекта:

```bash
python -m scripts.replay_event_signal --events docs/examples/finam-m1/events.json --live
python -m scripts.replay_event_signal --events docs/examples/finam-m1/events.json --symbol GMKN --live
```

Пример использует 30 минут основной сессии 20.11.2026 для контроля
источника. Первая команда проверяет GAZP, вторая GMKN в том же окне.
В отчёте успешного прогона поле `candles_checked` равно 30. Для дальнейших прогонов подставьте время свежего события с
часовым поясом. По документации Finam глубина M1 составляет семь дней.
При работе из интерактивного терминала ключ запрашивается скрытым вводом,
если `FINAM_API_TOKEN` не задан. В автоматическом запуске ключ передаётся
через окружение. Сохранить свечи для повторного прогона можно с
`--save-candles finam-m1.json`, использовать снимок — с
`--candles finam-m1.json` и тем же файлом события.

Для бэктеста с выходом по истечении окна запросите также свечу, которая
открывается в момент истечения. В отчёте для провайдера `finam` суммы
указаны в рублях.

```bash
python -m scripts.replay_event_signal --events docs/examples/finam-m1/events.json --symbol GMKN --live --include-expiry-open --save-candles gmkn-m1.json
python -m scripts.backtest_event_m1 --events docs/examples/finam-m1/events.json --symbol GMKN --case-id gazp-m1-recent-session --candles gmkn-m1.json
```

Для GAZP укажите `--symbol GAZP` и отдельный файл свечей. Идентификатор
события в примере обозначает одно и то же контрольное окно для обоих тикеров.

Контракт M1 проверен имитацией ответа API. Получение минутных свечей с
боевым ключом, семантика метки времени и полнота реальной выдачи требуют
живой приёмки. Дневной сбор использует прежний сценарий.
[Документация Finam](https://api.finam.ru/getting-started/bystryy-start/poluchit-kotirovku-i-istoriyu/).

## Минутные данные через API AEGIS

Авторизованному пользователю AEGIS доступны `GET /api/v1/market/finam/minutes`
для бумаг реестра и IMOEX и `GET /api/v1/market/ipos` для поиска компаний. Пример
параметров запроса M1:

```text
symbol=GAZP
start=2026-11-20T07:10:00Z
end=2026-11-20T07:40:00Z
```

Для проверки Норникеля используйте `symbol=GMKN` с тем же окном.
Верхняя граница исключается. `READY` означает, что вернулось по свече на
каждую минуту окна без отбраковки. `PARTIAL` показывает валидные свечи в
неполном окне, `EMPTY` — пустой ответ, `INVALID` — ответ, в котором все
строки отклонены. `rejected` содержит только счётчики по причинам:
некорректное время, выход за окно, неверные цены или объём, повторы и
конфликтующие свечи. Исследовательский прогон по-прежнему требует
полного валидного окна. Дневные таблицы не используются.

В Windows запустите `scripts/start_finam_dashboard.ps1` с параметрами
`-Repository`, `-Revision` и `-EnableFinamApi`. Этот режим открывает API на
`127.0.0.1` с отдельным процессом, запрашивает ключ скрыто и выводит ссылку
на `/docs`. Ключ передаётся в окружение этого процесса. API AEGIS принимает
JWT от входа в AEGIS. IPO работает с публичными источниками и доступен при
отсутствии ключа Финама.

## Онлайн-режим бумаг реестра

В режиме запуска `-EnableFinamApi` войдите в дашборд AEGIS и нажмите
**Онлайн · M1**. Список бумаг дашборд получает из
`GET /api/v1/market/instruments`. Сразу после входа он запрашивает
двухчасовой снимок через `GET /api/v1/market/finam/minutes` для каждой бумаги
и IMOEX — независимо от потока. Авторизованный маршрут
`GET /api/v1/market/finam/stream` передаёт события NDJSON. Сервер
подписывается на QUOTES и BARS (M1) для всех инструментов реестра по
WebSocket Финама. Пока открыт режим M1, снимок обновляется раз в минуту без
ожидания потока. После переподключения дашборд сразу перечитывает окно REST,
пропущенные закрытые минуты дополняются, повторы удаляются.

У каждой бумаги в списке свой статус и время последнего обновления по МСК:
«Поток», «Ждём поток», «История M1», «Устарело» (поток прерван, показаны
последние данные) или «Ошибка подписки». Отказ Финама по одному тикеру
(`symbol_error`) не останавливает остальные. Состояние истории
показывается для выбранного инструмента, состояние потока — отдельно. Если поток недоступен, график дополняется свечами из
REST, а более старая потоковая котировка уступает свежей свече. Сбой
помечается этапом: авторизация, подключение, подписка или
получение данных. В журнал сервера пишутся только безопасный `code` и
`stage`. Подключённый поток может ожидать сделки, когда рынок закрыт.
При некорректной отдельной записи поток показывает предупреждение и
продолжает передавать валидные записи.
Для живой приёмки в торговое время проверьте обновление цены и минут по
всем тикерам реестра. [Спецификация WebSocket Финама](https://api.finam.ru/docs/async-api/).

## Пять бумаг, IMOEX, новости и задержка реакции

Реестр `config/portfolios/russian-research.json` — единственный список
бумаг. Его читают API (`/market/instruments`, `/finam/minutes`,
`/finam/news`), адаптер, поток, `python -m worker collect` и `finam-daily`
без `--symbols`, а также дашборд. Время хранится в UTC, показывается по МСК.

| Тикер | Компания | Символ Финама |
|---|---|---|
| GAZP | Газпром | `GAZP@MISX` |
| GMKN | Норникель | `GMKN@MISX` |
| SBER | Сбербанк | `SBER@MISX` |
| YDEX | Яндекс | `YDEX@MISX` |
| X5 | ИКС 5 | `X5@MISX` |
| IMOEX | Индекс МосБиржи (индикатор) | `IMOEX@MISX` — требует живой проверки |

Идентификаторы сверяются с `GET /v1/assets/{symbol}` в живой проверке ниже.
До неё символ IMOEX помечен в API как `LIVE_CHECK_REQUIRED`. Акции и индекс
сравниваются только на совпадающих закрытых минутах.

**Устойчивость.** Все запросы проходят через общий бюджет 200 запросов в
минуту. Ответ 429 переводит адаптер в паузу на `Retry-After` (не больше
120 с); `with_retries` и переподключение потока ждут не меньше этого срока.
Ошибка одного тикера в дневном сборе, REST-докачке или подписке остаётся в
его статусе.

**Новости.** `GET /api/v1/market/finam/news?hours=24` читает
`GET /v1/news/sources` и `GET /v1/news/history` с фильтром по пяти тикерам,
проходит курсоры страниц (повтор курсора — ошибка) и сохраняет каждую
версию в таблицу `market_news`: источник, ID, версию, время публикации,
время получения Финамом и первое время получения AEGIS. Повтор не
сохраняется второй раз, исправление — новая версия, удалённая новость
снимает сигнал. Статус ленты (`OK`, `NOT_CONFIGURED`, `NO_ACCESS`,
`RATE_LIMITED`, `UNAVAILABLE`) показывается отдельно от котировок.

**Сигналы (правила PR #12).** Публичная или редакционная новость даёт
`WATCH`, раскрытие источника из `news_sources.official` реестра — `CONFIRMED`.
Пока список официальных источников пуст, лента Финама даёт только `WATCH`.
Для X5 рекомендация дивидендов, решение акционеров и дата отсечки — разные
события. Сигнал появляется не раньше `max(время публикации, время
получения AEGIS)`; новость с будущей датой публикации сигнала не даёт.
Заявки не формируются (`entry_candidate: null`).

**Реакция цены.** `worker/event_reaction.py` берёт базу — последнюю минуту,
закрытую к моменту доступности события, — и окно закрытых M1 после него.
Отчёт содержит задержки «публикация → Финам» и «публикация → AEGIS».

Воспроизведение (PowerShell, ключ только в окружении процесса):

```powershell
$env:DATABASE_URL = 'postgresql://aegis:aegis123@127.0.0.1:55432/aegis_stage'
$env:REQUIRE_DATABASE = '1'
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m pytest -q
# Живая проверка в торговое время: GetAsset, последняя D1 и закрытая M1,
# поток QUOTES/BARS и доступ к новостям по каждому тикеру и IMOEX.
$env:FINAM_API_TOKEN = '<ключ «Просмотр»>'
.\.venv\Scripts\python.exe scripts\finam_watch_check.py --stream-seconds 60
# Постоянный монитор: снимок состояния и задержек в data/finam-monitor.json.
.\.venv\Scripts\python.exe -m worker finam-monitor --status-file data\finam-monitor.json
Remove-Item Env:FINAM_API_TOKEN
```

Без ключа `finam_watch_check.py` возвращает `NOT_CONFIGURED` (код 2).
`LIVE_CHECKED` (код 0) означает, что все идентификаторы подтверждены, у
каждой бумаги есть D1 и закрытая M1, а поток открылся.
